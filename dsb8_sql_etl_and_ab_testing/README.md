# Оценка влияния социальной фичи на вовлеченность пользователей (A/B-тест)

## Бизнес-контекст и цель
Образовательная платформа внедрила новую функциональность — «Ленту активности» (Newsfeed), где студенты видят прогресс друг друга. 
Основная гипотеза продукта заключалась в том, что социальное доказательство (peer pressure) мотивирует студентов начинать выполнение заданий раньше, сокращая разрыв между дедлайном и первым коммитом. 

Цель данного исследования — подготовить надежную витрину данных из сырых логов и провести A/B-тест для статистической оценки влияния фичи на поведение пользователей.

## Технический стек
* Язык: Python 3 (Pandas)
* База данных: SQLite3
* Методологии: ELT (Extract, Load, Transform), A/B-тестирование, корреляционный анализ
* Инструменты: Jupyter Notebook, Git

## Ключевые этапы реализации

### 1. Извлечение и очистка данных (Extract)
Анализ начинался с работы с сырыми логами в таблицах `pageviews` (логи просмотров) и `checker` (логи проверки задач). 
На этом этапе были реализованы строгие правила фильтрации на уровне SQL-запросов для обеспечения чистоты данных:
* Исключены технические аккаунты (администраторы).
* Отфильтрованы некорректные статусы проверки (оставлены только `status = 'ready'`).
* Учтены только первые попытки сдачи заданий (`numTrials = 1`), так как именно они отражают момент начала работы над лабораторной.
* Оставлены только те лабораторные работы, которые были активны во время проведения эксперимента.

### 2. Проектирование аналитической витрины (Transform & Load)
Для дальнейшего анализа была спроектирована и создана денормализованная витрина `datamart` непосредственно в базе данных SQLite.
* С помощью сложных SQL-запросов с использованием JOIN и подзапросов данные из `pageviews` и `checker` были объединены.
* Рассчитаны ключевые временные метрики: `first_commit_ts` (время первого коммита) и `first_view_ts` (время первого просмотра ленты).
* Для корректного формирования контрольной группы (пользователи, которые ни разу не заходили в ленту) были обработаны пропуски: значения `first_view_ts` в контрольной группе заполнены средним значением из тестовой группы. Это позволило привести группы к единой временной шкале для сравнения.

### 3. Расчет метрик и исследовательский анализ
* Рассчитана целевая метрика: дельта (разница) между дедлайном лабораторной работы и первым коммитом пользователя в часах.
* Из расчета были исключены выбросы: лабораторная работа `project1` имеет нестандартно длинные дедлайны и большое количество коммитов, что искажало бы общую картину.
* Проведен корреляционный анализ для проверки связи между количеством просмотров ленты (`pageviews`) и средней дельтой времени до первого коммита.

### 4. Проведение A/B-теста
Для проверки основной гипотезы было проведено сравнение поведения двух когорт:
* **Тестовая группа:** пользователи, взаимодействовавшие с лентой активности. Для них рассчитана средняя дельта «до» и «после» момента первого посещения страницы.
* **Контрольная группа:** пользователи, не посещавшие ленту. Для них рассчитана аналогичная дельта относительно условной точки отсчета (среднего времени первого просмотра тестовой группы).

## Результаты и выводы по данным

* **Подтверждение гипотезы:** Анализ показал, что в тестовой группе после первого взаимодействия с лентой активности средняя дельта (время до первого коммита) сократилась. В контрольной группе, где фича не использовалась, статистически значимого изменения метрики во времени не зафиксировано. Это указывает на то, что механика peer pressure работает и стимулирует более раннее начало работы над заданиями.
* **Корреляция активности:** Выявлена корреляция между количеством просмотров ленты и своевременностью сдачи работ. Пользователи, которые чаще взаимодействовали с лентой, в среднем начинали выполнять лабораторные работы раньше.
* **Эффективность ELT-подхода:** Создание витрины `datamart` на уровне СУБД позволило перенести тяжелые операции фильтрации и агрегации на движок базы данных, что оптимизировало дальнейшую работу с данными в Pandas и обеспечило воспроизводимость расчетов.
